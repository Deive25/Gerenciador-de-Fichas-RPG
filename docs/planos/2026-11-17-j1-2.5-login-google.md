# J1 2.5: login com Google (plano de implementação)

> O processo é o enxuto (spec §9): preparação; backend e front em paralelo (Tarefa 1 e Tarefa 2); revisão independente no fim. Os passos usam checkbox (`- [ ]`).

**Objetivo:** botão "Continuar com o Google" em Entrar e Cadastrar. A API valida o *ID token* e devolve os tokens próprios do J1.

**Arquitetura:** o front carrega o Google Identity Services sob demanda e envia o `credential` para `POST /auth/google`. A API confere o token com um `NimbusJwtDecoder` RS256 privado, que recebe as chaves de um bean `JWKSource`, aplica as regras da conta (spec §3) e emite o par de tokens do 2.2.

**Stack:** Spring Boot 4.1.2, Java 21, Spring Security (resource server, Nimbus), PostgreSQL 17 com Flyway, Angular 22 (signals), Vitest.

**Spec:** `docs/specs/2026-11-17-j1-login-google-design.md` (os executores leem as duas).

## Restrições globais
- **Nenhuma dependência nova**, nem no `pom.xml` nem no `package.json`.
- **Nada de `npm ci` ou `npm install`:** o `ng serve` está no ar. No front, use só `npx ng test --watch=false` e `npx ng build`.
- **Nada de Maven na pasta real:** a API está no ar com o devtools. Copie para uma pasta temporária (`tar --exclude=./target`) e rode `./mvnw -B clean verify` lá.
- **Client ID** (público): `181222736917-1k8vp73jptcmrbgceam718qoa55p0i39.apps.googleusercontent.com`.
- **Mensagens exatas:** "Não foi possível entrar com o Google. Tente de novo." · "Confirme o seu e-mail no Google antes de entrar." · "Este e-mail já está ligado a outra conta do Google." · "O login com o Google não está disponível agora. Use o e-mail e a senha."
- **Logs:** só o id do usuário; nunca o token, o e-mail ou o nome.
- **Os testes existentes não mudam de asserção.** A única exceção é o `EsquemaBancoTest` (coluna `google_sub`).

## Foco da revisão
1. Um segundo bean `JwtDecoder` no contexto quebraria a validação dos nossos tokens HS256. O decoder do Google fica **privado** no `VerificadorDoGoogle`, e um teste confere que `GET /me` com o nosso token continua 200.
2. A ligação de contas precisa revogar **todas** as famílias do usuário, inclusive as de outro aparelho, e **só as dele**.
3. Um `email_verified` ausente, ou vindo como a string `"true"`, conta como **não** verificado. Só o booleano `true` passa.
4. O callback do Google dispara de novo, por um duplo clique ou por dois botões, enquanto o primeiro pedido está em voo: só deve sair um `POST`.
5. O botão a 375 px: a largura é limitada a 200–400 px, e a página não ganha rolagem horizontal.

**Detalhes do `VerificadorDoGoogle`:**
- No construtor, recebe `JWKSource<SecurityContext> chavesDoGoogle`, `@Value("${app.google.client-id}")` e o `Clock`.
- Monta o `NimbusJwtDecoder` com `withJwkSource(...)` e `jwsAlgorithm(RS256)`. **Confirme o método no Spring Security do Boot 4.1.** Se não existir, use `new NimbusJwtDecoder(DefaultJWTProcessor)` com um `JWSVerificationKeySelector(RS256, fonte)`.
- **Os validadores** são o `JwtTimestampValidator` com o `Clock`, o `iss` ∈ {`https://accounts.google.com`, `accounts.google.com`} e o `aud` contendo o client ID.
- **Nunca é anotado como `@Bean JwtDecoder`.**
- Qualquer `JwtException` vira `LoginGoogleRecusadoException("Não foi possível entrar com o Google. Tente de novo.")`.
- O `email_verified` só é `true` se a claim for o `Boolean.TRUE`.
