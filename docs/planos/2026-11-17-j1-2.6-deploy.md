# J1 2.6: deploy gratuito (plano de implementação)

> O processo é o enxuto: preparação, backend e front em paralelo (Tarefa 1 e Tarefa 2) e revisão independente no fim. Os passos usam checkbox (`- [ ]`).

**Objetivo:** o J1 num link público e gratuito, com uma demonstração que cria a própria conta, a mesa ao vivo em duas abas, o aviso de "acordando o servidor" e a publicação automática depois do CI.

**Arquitetura:**
- front estático no Cloudflare Pages, com a CSP no `_headers`;
- API Spring Boot em Docker no Render gratuito;
- PostgreSQL no Neon;
- o job `deploy` do CI chama o *deploy hook* do Render e o `wrangler pages deploy`.

**Spec:** `docs/specs/2026-11-17-j1-deploy-design.md`. Os executores leem a spec inteira.

## Restrições globais
- **Dependência nova:** só o `spring-boot-starter-actuator` no `pom.xml`. O `package.json` não muda; o `wrangler` roda por `npx wrangler@<versão fixa>`, sem instalar.
- **Nada de `npm ci` nem de `npm install`:** o `ng serve` está no ar e trava o `node_modules`. No front, use só `npx ng test --watch=false` e `npx ng build`.
- **Nada de Maven na pasta real:** a API está no ar com o devtools. Copie a pasta para uma pasta temporária (`tar --exclude=./target`) e rode lá o `./mvnw -B clean verify`.
- **Nenhum segredo no repositório:**
  - URLs, tokens e senhas de produção só entram nas variáveis do Render e nos segredos do GitHub;
  - o repositório só leva os nomes públicos (`<projeto>.pages.dev`, `<api>.onrender.com`), que o Arthur informa na Tarefa 4. Até lá, use `fichas-rpg` e `fichas-rpg-api`.
- **Mensagens exatas:**
  - "Ver demonstração"
  - "Entrar como jogador de demonstração"
  - "Abra este convite em outra aba ou no celular para entrar como jogador."
  - "Acordando o servidor gratuito… pode levar até 2 minutos ({N}s)."
  - "O servidor não respondeu. Tente recarregar a página."
  - "Muitas tentativas. Tente de novo em alguns minutos." (429)
- **Logs:** só ids, nunca IP completo, e-mail, token ou nome.
- **Os testes existentes não mudam de asserção.** A única exceção é o `EsquemaBancoTest` (V14).

## Foco da revisão
1. Uma conta demo **não pode** entrar numa campanha real, nem por convite nem pelo id. A limpeza apaga **só** os demo com mais de 24 h, e tudo o que é deles, sem tocar em conta real (teste com uma conta real na mesma campanha que um demo).
2. O limite de tentativas usa o IP do visitante, e não o do proxy do Render. O `X-Forwarded-For` enviado direto, sem o proxy, não pode zerar o contador.
3. A sessão demo fica no `sessionStorage`, e a sessão normal continua no `localStorage`. A troca entre as duas não pode deixar um refresh velho para trás nem quebrar a trava Web Locks da renovação.
4. Nenhuma violação de CSP no console com o build de produção, no login, no botão do Google, na ficha, no retrato, no dado 3D e no WebSocket.
5. O container sobe com 512 MB (`docker run -m 512m --cpus 0.1`), e o tempo até o liveness responder fica medido.
