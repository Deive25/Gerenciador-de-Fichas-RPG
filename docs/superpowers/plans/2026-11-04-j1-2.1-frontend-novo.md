# Incremento 2.1: frontend novo (Angular 22) — plano de implementação

> **Para agentes:** sub-skill obrigatória: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para executar este plano tarefa por tarefa. Os passos usam a sintaxe de checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** substituir o frontend Angular 13 por um novo em Angular 22, com o visual "investigação sombria" e layout pensado primeiro para o celular. Ele precisa cobrir tudo o que a aplicação faz hoje: listar, ver, criar, editar e excluir fichas, e rolar teste de perícia.

**Arquitetura:** SPA standalone (sem NgModules) com *signals* e a sintaxe `@if/@for`. As telas ficam em `src/app/fichas/` e falam com a API REST atual (contrato do 1.6), por meio de um serviço único. O layout tem duas formas:
- no celular, uma tela por vez, com barra no topo e navegação embaixo;
- a partir de 900 px, duas colunas: lista à esquerda e ficha à direita.

A API **não muda** neste incremento.

**Stack:** Angular 22.2 (CLI 22.2), Angular Material 22.2 (+ CDK), TypeScript da versão do CLI, Vitest (executor padrão do `ng test`), Node 24 (local 24.21; o Angular exige `^22.22.3 || ^24.15.0`).

**Spec:** `docs/superpowers/specs/2026-11-04-j1-fase-2-design.md` (§7 Frontend, §9 linha 2.1).

## Restrições globais

- API base `http://localhost:8080`, via `environment.apiUrl`. O CORS da API já libera `http://localhost:4200`.
- Contrato atual (não muda):
  - `GET/POST /fichas`;
  - `GET/PUT/DELETE /fichas/{id}`;
  - `POST /fichas/{id}/testes-de-pericia` com corpo `{"pericia": "<CODIGO>"}`, que devolve `{pericia, nome, valor, rolagem, resultado}`.
- Erros da API chegam em ProblemDetail (`application/problem+json`), com `title`, `detail`, `status` e, na validação, `errors` (campo → mensagem). O JSON de entrada é estrito: não envie chaves fora do contrato. O `id` no corpo é ignorado.
- Campos da ficha:
  - texto: `jogador`, `personagem`, `genero`;
  - números: `idade`, `vidaAtual`, `vidaMaxima`, `sanidadeAtual`, `sanidadeMaxima`, `forca`, `destreza`, `constituicao`, `inteligencia`, `carisma`, `sabedoria`, `tamanho`, `sorte`, `poder`;
  - `pericias`: objeto `{CODIGO: número}` só com as preenchidas.
- Validação, igual à da API:
  - `jogador`, `personagem` e `genero` são obrigatórios, com no máximo 255 caracteres;
  - números são inteiros opcionais, sem mínimo nem máximo (ADR 0008);
  - campo vazio é enviado como `null`.
- Regra do teste de perícia (servidor): `rolagem ≤ ⌊valor/5⌋` dá `SUCESSO_EXTREMO`; `rolagem ≤ valor` dá `SUCESSO`; o resto é `FALHA`. Perícia sem valor vale 0 e sempre falha.
- Visual (variáveis CSS em `styles.scss`):

  | Variável | Valor |
  |---|---|
  | `--cor-fundo` | `#12151c` |
  | `--cor-superficie` | `#1a1f2a` |
  | `--cor-borda` | `#2b3240` |
  | `--cor-texto` | `#d8dde6` |
  | `--cor-texto-suave` | `#8a93a3` |
  | `--cor-titulo` | `#e9dcc0` |
  | `--cor-acao` | `#c9a45c` |
  | `--cor-vida` | `#d0533f` |
  | `--cor-sanidade` | `#4fb38c` |

  Títulos em `Georgia, 'Times New Roman', serif`; texto em `system-ui, 'Segoe UI', Roboto, sans-serif`. Nenhuma fonte externa.
- Ponto de quebra do layout: `900px`.
- Arquivos e classes seguem o padrão do CLI 22: `ng generate component` cria `nome.ts`, `nome.html`, `nome.scss` e `nome.spec.ts`, sem o sufixo `.component`, com a classe em PascalCase.
- Textos de interface em português.
- Commits em português, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Nenhuma dependência além das criadas pelo `ng new` e do `@angular/material` (com o CDK).
- Comandos:
  - testes: `npx ng test --watch=false`;
  - build: `npx ng build`;
  - rodar com a API: `npm start`.

## Foco de revisão

1. **API inacessível ou "acordando"** (status 0): o usuário vê "Servidor indisponível" com o botão "Tentar de novo", nunca uma tela em branco. Teste na Tarefa 4 (mapeamento) e na Tarefa 5 (tela da lista).
2. **Erro de validação do servidor num campo que o cliente aceitou** (ex.: regra futura ou corrida): a mensagem de `errors.<campo>` aparece embaixo do campo certo. Teste na Tarefa 7.
3. **Ficha apagada em outra aba** (`GET /fichas/{id}` → 404): a tela mostra "Ficha não encontrada" com link para a lista. Teste na Tarefa 6.
4. **Número não inteiro ou texto em campo numérico** ("1.5", "abc"): o formulário bloqueia o envio e mostra "Use um número inteiro"; o vazio vira `null`, nunca `0` nem `""`. Teste na Tarefa 7.
5. **Toque duplo em 🎲 ou em Salvar:** só uma requisição sai; o botão fica desabilitado até a resposta. Teste na Tarefa 6 (🎲) e na Tarefa 7 (Salvar).
